## Architecture

### Backend: modular monolith by team ownership

`backend/src/main/java/com/localpress/` has one package per business module: `advertising` (SV1), `editorial` (SV2), `reader` (SV3), `finance` (SV4), `content`/`delivery`/`administration` (SV5), `identity` (auth/users), `shared`. Each module has its own `controller/service/repository/model/dto`. Modules do not call into each other's internals (Rule 17); cross-module coupling goes through:

- `shared.event.PaymentSuccessEvent` / `RefundCompletedEvent`: finance publishes, the owning module (`reader`, `advertising`) listens with `@EventListener` to grant or revoke rights. Finance never writes `article_purchases`, `subscriptions` or `ad_campaigns`.
- Scalar foreign keys (`Long userId`, `targetId`) rather than JPA relations across modules.
- `shared.response.ApiResponse` envelope and `shared.exception.AppException` for errors.
- `shared.security.SecurityConfig` is the single Spring Security config (stateless, HTTP Basic against seed users). Do not add another `SecurityConfig` bean in a module.

Money flow in `finance`: module creates a pending target record, calls `POST /api/v1/finance/orders`, frontend navigates to the shared `/payment/:orderCode` page. All orders are paid from the LocalPress wallet; a shortfall creates a TOPUP order (`topup_for_order`). Every incoming payment (SePay webhook, SePay API sync, dev simulation) goes through `SepayGatewayService.receive`, which logs to `sepay_webhook_logs` (unique `sepay_id`) and is idempotent; wallet entries are unique on `(transaction_id, direction)`. Refunds are four-eyes (propose, then manager approve) and capped by amount actually collected.

### Frontend: feature folders mirroring backend modules

- `src/app/`: `config.ts` (`APP_CONFIG`, `UserRole`), `router.tsx` (all routes, wrapped in one of 4 layouts in `src/layouts/` plus `ProtectedRoute`), `providers.tsx`.
- `src/features/<module>/{api,pages,components,types}`: each module's `api/index.ts` calls the shared `httpClient` (`src/lib/http/client.ts`), which routes either to `src/mocks/handlers` + `mocks/store.ts` (mock mode) or to real `fetch` with Basic auth.
- Shared UI in `src/components/ui` and `src/components/shared` (`StatusBadge`, `EmptyState`, `ConfirmDialog`, `ThemeToggle`); formatting must go through `@/lib/format`. Finance screens use the primitives in `src/features/finance/components/LedgerUI.tsx`.
- Import alias `@` = `frontend/src`.
- Post-login redirect must use `PERMISSION_CHECKERS.getDefaultBackofficeRoute(user.role)`; never hardcode a module URL.

Frontend conventions and screen templates: `.agents/skills/localpress-frontend/SKILL.md` and `.agents/skills/taste-skill/`. UC to route/controller/table mapping for reviews: `.agents/skills/iter-review/SKILL.md`.
